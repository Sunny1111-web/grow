# 向光而生 设计基线

版本：v1.0　日期：2026年9月5日　用途：四份设计文档的共同约束与数值入口。

## 来源与决策状态

原始依据为上级目录的《Grow 游戏创新创作大赛——项目设计上下文与后续深化说明》。引用对话《设计生长主题游戏方案》的在线全文在本次编写时未能读取，不能将本文件称为对话逐字整理。原始方向保留；引擎与协作方式已由用户确认，具体数值、工期与验收指标为本次设计建议，尚未经过实际开发和玩家测试。

核心支柱：身体即地图；生长即移动；修剪也是成长。玩家控制固定种子上的植物网络，只能通过生长探索。2D 横向剖面，手绘植物与低饱和城市废墟。

## 制作边界

用户已确认使用 Godot。以 Windows 键鼠单机为首发验证平台，使用项目已准备并实际运行核实的 Godot 4.7.2 stable（构建 ed1daf0bf），采用 GDScript 与 Compatibility 渲染器。具体 API 以本机版本验证为准。

团队已确认：用户与 GPT-6 Astra 协作。用户是唯一人类制作人，负责最终决策、试玩体验、美术取舍、素材授权和提交；GPT-6 Astra 协助规格、代码、自动检查与文档，不能折算成一名独立全职员工。排期假设用户每周可投入20小时、12周，共240人工小时；P0计划192小时，预留48小时。AI执行时间不另计成人工产能，人工审查与集成包含在任务估算内。比赛截止日期与用户真实可用工时尚未提供，故使用相对周次。

P0 比赛 Demo：一间公寓加窗外视野，15～20分钟；根、藤、叶、强化枝干、分叉、攀附、光照与遮挡、水维护、局部枯萎、修剪、感知、救援、存档、结尾。P1 可选共生尾声，使P0与尾声合计20～30分钟；仅在P0验收和缓冲充足时启动。P2 完整版远期愿景：动物、花果、嫁接、天气昼夜、多关卡、生态结局。

## 统一术语与参数

所有数值均为原型起点，不是实测平衡结果。1世界单位记为1u；初始视野约16u×9u。

| 项目 | 设计基线 |
| --- | --- |
| 模拟 | 实时，固定0.1秒步长；菜单、感知、拖拽预览冻结模拟；生长动画0.6秒期间也冻结模拟 |
| 普通能量E | 初始30，上限40；不低于0；不充当健康值 |
| 根 | 每次长度0.8u，能量4，基础需水0.15 W |
| 藤 | 每次长度1.0u，能量5，基础需水0.35 W |
| 叶 | 每节点最多1片，能量3，基础需水0.8 W；健康强光叶产能1.6 E/秒 |
| 分叉 | 现有地上节点长第二条藤时额外付4 E；最多2个地上延伸子边，叶插槽独立 |
| 强化 | 将一条现有藤边变为枝干，付6 E、一次完成；需水0.5 W；重量与水阻见TDD |
| 光照 | 强1.0、普通0.6、弱0.2、暗0；不做实时昼夜 |
| 遮挡 | 每片叶3条采样射线；建筑完全遮挡；每层其他叶乘0.5；忽略被采样叶自身 |
| 地下水 | W1接入后可用供水12 W；W2是同一含水层更好的接入点，解锁总供水上限20 W，不能相加成32 W |
| 网络 | 有根树；交叉不嫁接，不形成运输环；同含水层只计一次；水分配与距离损耗由TDD明确定义 |
| 修剪 | 免费，能量返还为0；剪掉的后代失去活体功能，保留伤口和静态残枝；无撤销 |
| 侧芽 | 同一原始地上插槽首次人工剪边发一次侧芽权益，下一条藤基础费减2 E；不减分叉费，不叠加，重剪不重发 |
| 快速等待 | 长按F以3倍模拟速度催生；所有水与结构风险同步加速；资源够当前器官或出现危险时自动停止 |
| 救援 | 菜单始终可退守种子；清零E与普通活体，固定2根和子叶最多产18 E，可重复但不叠加；GDD/TDD定义恢复路线 |
| 硬上限 | 每关400条活体边、100片活叶、200个伤痕/残枝表现槽；达到上限有说明，不静默丢数据 |
| 视觉 | 灰蓝废墟、绿色植物、金色光、青蓝水；状态同时用形状、纹理、图标表达 |

## 统一验收方向

验证玩家每5～15秒是否有方向、器官、支点、光位或修剪选择。首轮至少5名未接触项目的玩家；4/5能在2分钟内完成第一根与接水，4/5在6分钟内形成首个正产能叶，4/5在提示不超过一次的情况下解决一次真实的结构或供水问题；无自然危机者另用固定危机存档补测，结果与首玩时长分开统计。P0首次完成中位时长15～20分钟；强制等待占可操作时间不超过10%。这些是目标，不是已经取得的结果。

源文档是创意来源；GDD定义玩家可观察规则，TDD定义算法与数据，美术指南定义表达和资源规格，项目管理文档定义范围与验收。变更需检查四份文档及本基线，不能各自维护冲突数值。
