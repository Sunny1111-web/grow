# 《向光而生》美术风格指南

版本：v1.0　日期：2026年9月5日　适用范围：P0 比赛 Demo，Windows 键鼠单机。

共同约束见[设计基线](00_设计基线.md)。本指南把已有的“手绘植物＋低饱和城市废墟”方向落实为可制作、可导入、可验收的资源规格。配套[生长美术规范板](assets/生长美术规范板.svg)为可编辑矢量设计图，表达构图与视觉语言，并非已经完成的游戏截图或最终手绘资产。

## 1. 视觉承诺与制作取舍

玩家最先看见的是一条仍在寻找光的生命，随后才看见废墟细节。整体以安静、克制的灰蓝房间容纳温暖的生长过程；圆润但不规则的植物轮廓与建筑的直线、缺口形成区别。植物沿家具和窗框留下路线，伤口与静态残枝保留过去的选择，终点是一室灰蓝中由玩家亲手增加的绿色。

P0 采用纯 2D 横向剖面：平面环境分层、程序曲线藤根、少量手绘叶形与纸纹。用户已确认使用 Godot，工程基线为本机已核实的 Godot 4.7.2 stable（ed1daf0bf）、GDScript、Compatibility 渲染器。项目的 Blender 目录为空，制作计划不依赖建模、雕刻、骨骼蒙皮或三维渲染。

| 可行路线 | 收益 | 成本与限制 | 本项目决策 |
| --- | --- | --- | --- |
| 大量逐帧手绘植物与独立环境插画 | 表情细腻，近景细节丰富 | 单人审稿、切图与动画量过高 | 留给远期宣传关键图 |
| 程序曲线＋少量手绘轮廓、纹理＋模块环境 | 植物能随玩家路线变化，资源可复用 | 需花时间打磨曲线接头与叶片姿态 | P0 主方案 |
| 完全几何占位 | 最快验证资源与结构规则 | 情感力度弱，容易像网络图 | W1～W3 原型和延期时的备用方案 |

唯一人类制作人为用户。GPT-6 Astra 可协助矢量草案、程序曲线、占位资源、批量命名和导入检查；最终风格判断、授权确认、试听、试玩与集成由用户完成。不能把 AI 运行时间当成额外全职人力，也不能把生成了规范板视为已交付所有最终素材。

## 2. 调色与材质

### 2.1 主色板

| 用途 | 色值 | 具体规则 |
| --- | --- | --- |
| 室内深阴影 | `#17252F` | 大面积安静底色；不能遮住可操作轮廓 |
| 废墟结构 | `#465B68` | 桌椅、墙体、管道的主要中间色 |
| 褪色墙面 | `#87969C` | 背墙斑驳与远处建筑，压低局部对比 |
| 纸白与 UI 正文 | `#E6E0CC` | 文字、选中细轮廓、小面积高光 |
| 健康植物 | `#6F9E62` | 叶片主色，枝条更深；不能只靠绿色表明健康 |
| 新芽高光 | `#B4D184` | 新生尖端和叶脉，限制高光面积 |
| 光照 | `#E7C46A` | 窗口、光域边界、光能图标；用疏线纹区分水 |
| 水源 | `#67B8C6` | 水纹、滴形、感知时的供水路径 |
| 可处理的风险 | `#D79B67` | 萎蔫提示、结构风险、修剪范围；配不同图标 |
| 失活组织 | `#837262` | 卷曲叶和静态残枝；降低饱和但保留外轮廓 |

灰蓝环境约占正常画面 70%～80%，植物 10%～20%，金色与水色合计尽量低于 10%。比例是构图检查方向，不按像素强制计算。颜色恢复首先来自新增植物；P0 结尾只允许轻微提亮窗外与室内环境，不能把整张背景染绿来替代玩家成长。

### 2.2 三类材质，少量笔触

- 植物：轮廓完整、左右不完全对称。每片叶一条主脉加 2～4 条短支脉；叶缘只有少量轻微缺口。墨线随宽度缓慢变化，不能每帧抖动。
- 建筑：几何大形、局部掉漆、少量裂缝。每个家具最多一块明面、一块暗面与少量边缘破损；装饰裂缝不能画成可攀附提示。
- 土壤：一块暗色底加一张可重复颗粒纹理，水源通过波纹与滴形标记从颗粒中显现。先保证根尖可见，再增加碎石。

避免全屏重噪声、彩色轮廓光、常驻发光描边。可以只用一张 256×256 的细颗粒纸纹，以低透明度在静态背景合成中复用；纹理不携带玩法信息。

## 3. 尺度、构图与图层

参考视口 1600×900，对应 16u×9u；美术换算建议 1u＝100 Godot 像素，工程最终换算由 TDD 统一。资源在参考视口下制作和验收，另检查 1280×720 与 1920×1080 的完整界面。窗口适配需保持世界比例，不能把枝条横向拉长以填满屏幕。

| 元素 | 参考视口中的外观 | 交互要求 |
| --- | --- | --- |
| 根 | 宽约 3～5px，土色偏暖，尖端变细 | 感知时增加水色侧线，选中才显示节点圈 |
| 嫩藤 | 宽约 6～9px，略微弯曲 | 保持完整外轮廓，预览与实际路径能对应 |
| 强化枝干 | 宽约 10～15px，双边缘与短木纹 | 与嫩藤不只做颜色差异 |
| 叶片 | 约 36～50px 长，叶柄统一接点 | 轮廓与朝向支撑采光阅读；点击范围与外观分开 |
| 生长端点 | 本体 8～12px，悬停出现外圈 | 可点击范围目标不小于 24px；缩小视图仍保持可点 |
| 图标与文字 | 主要图标 24～32px；正文目标 18px | 低分辨率下不小于 16px；依工程实际字体复验 |

图层从后向前为：远城剪影 → 室外天空与窗光底色 → 室内背墙 → 家具/地板/可攀附轮廓 → 活体网络 → 伤口和局部状态 → 操作预览 → HUD。地下土层单独遮罩并让根位于其上方。前景可以压暗边缘，但不要覆盖支点、叶片与选择提示。

相机用露出房间、到达第一束光、伸出窗外三个节点建立节奏。P0 使用平移和缓慢拉远，不做镜头震动。镜头拉远后保留“种子—主要根—主枝—窗外”的连续读图路线；不是用更多装饰把空白填满。

## 4. 植物造型、曲线与状态

### 4.1 形态组件

一段生长对应一条逻辑边，但呈现可以是少量采样点构成的平滑曲线。用固定随机种子生成每条边的小偏差，读档保持同样外形。新生藤遵循预览路径，不能为了“更自然”在确认后明显改变终点。P0 用 `Line2D` 或一个批量绘制节点实现曲线，叶、芽、伤口用 `Sprite2D`；需要的具体绘制接口以 TDD 和本机验证为准。

端点与连接处使用圆润接头并盖住细小接缝。根与藤只保留 2 种边缘纹理，枝干另有一组短木纹；不能为每个长度和弯曲角度画一套切片。叶片先画一套通用母形，再给健康、萎蔫、枯萎三个轮廓，死亡沿用枯萎轮廓并切换灰褐材质。左右镜像可用于健康叶，叶脉和伤痕不要每帧重新随机。

Godot 的 `Line2D` 可由点列和宽度控制曲线外形，并支持纹理模式。本项目只选择必要能力；首版优先平色宽线和叶贴图，纹理连续性通过样例验收后再启用。[Godot Line2D 文档](https://docs.godotengine.org/en/stable/classes/class_line2d.html)

### 4.2 状态必须同时可见、可解释

| 逻辑状态/事件 | 形状或纹理 | 辅助图标/文字 | 声音与动效 |
| --- | --- | --- | --- |
| 健康 | 叶片张开、叶柄有支撑，完整主脉 | 选中时可见稳定供水与当前产能 | 缓慢轻摆，静止也能辨认 |
| 萎蔫 | 叶尖下垂，叶面收拢；保持可恢复的饱满边缘 | 空心水滴＋“供水不足” | 首次进入提示一次，恢复时抬起 |
| 枯萎 | 叶缘明显卷曲、出现 2～3 处干裂纹 | 裂纹水滴＋“正在枯萎” | 摆动趋弱，不持续报警 |
| 死亡/失活 | 固定卷曲姿态、灰褐色、无生长端点 | 划线叶图标＋“已失活” | 停止摆动与资源粒子 |
| 结构风险 | 枝条视觉下垂，并在危险边加短斜杠 | 三角支撑图标＋“需要支撑” | 一次轻微绷紧声，危险加深不闪屏 |
| 已攀附 | 接触点出现两道短环抱线 | 感知时固定夹持图标 | 吸附时短促、轻的木质声 |
| 强化完成 | 线宽增加，显露木纹，接头完整 | 双线枝干图标 | 0.3 秒厚度过渡，可随低动态模式关闭 |
| 遮光 | 叶面带稀疏斜影条，叶仍保持健康轮廓 | 半遮太阳＋“受遮挡” | 不额外播放缺水声 |
| 修剪预览 | 待断连子树统一半透明斜线；切口亮起 | 剪刀＋边数/叶数/需水变化，旁示能量返还0 | 按下前保持静态，待用户确认 |
| 修剪完成 | 伤口小截面、残枝固定、附近一个侧芽 | 有效侧芽标记；消费后恢复普通节点外观 | 一次清脆短音，随后一小段静默 |
| 救援可用 | 种子外壳出现独立细环，指向固定恢复动作 | 种子储备图标＋“退守种子”，菜单始终可用 | 与普通能量提示分开，不表现成无限生命 |

状态切换阈值、倒计时与能否恢复由 GDD/TDD 决定，美术不能自建一套健康计时器。结构下垂只能在视觉上偏移中段，逻辑端点、碰撞、采光与攀附采样点保持一致；若技术方案最终改变逻辑路径，必须同时重做对应预览和所有采样。缺水与结构风险同时出现时，两个小图标并列，不能把所有问题都显示为橙色闪光。

每关上限为 400 条活体边、100 片活叶、200 个伤痕/残枝表现槽。残枝表现是静态、不碰撞、不输水的记录，既不重建成物理对象，也不重新成为可攀附表面。达到上限的逻辑处理由 TDD 定义，美术不得静默丢失伤痕。远景可以降低细节，但仍可在选中时恢复可读状态。

### 4.3 生长与静态生命感

| 动效 | P0做法 | 限制 |
| --- | --- | --- |
| 单次生长 | 0.6秒沿路径揭示线段，尖端比枝身略亮 | 动画期间冻结模拟，与共同基线一致 |
| 叶片展开 | 同一叶柄固定点，缩放与旋转组合 | 不画逐帧长序列；展开不能改变玩法朝向 |
| 呼吸/轻摆 | 2～4秒一周期、2°～4°视觉摆动，按节点固定相位 | 只摆叶片外观；低动态设置停止摆动 |
| 水连通 | 连接确认时最多3个小点沿可见主路径移动 | 常态不把全网画成流动电路；感知时也限定数量 |
| 窗外揭示 | 约2秒平移/拉远＋音乐淡入 | 最终植物使用实际玩家网络，不切换成预画大树 |

节约工作量的顺序：先曲线连续与形状区别，再三个叶姿态，再一次性提示，最后纸纹和环境轻动。延误时省掉连续水粒子、漂浮尘埃与视差；保留状态轮廓、预览和修剪反馈。

## 5. 场景、感知与界面

### 5.1 公寓资产语言

P0 只做一间废弃公寓和窗外远景。破损来自重复使用的裂缝、掉漆、缺角贴花，不为每种破损另画家具。椅背、桌沿、管道、窗框等实际可攀附处保留连贯而偏亮的边缘；普通背景线条降低对比，避免暗示不存在的攀附能力。看似接触却不能攀附的装饰应改形或移到背景层。

关键物件只选一个，即GDD的M1旧水壶；它主要承担空间记忆，不在 P0 引入新器官或额外叙事系统。窗外建筑采用两层剪影和少量窗格，远处生命痕迹只是一点不抢眼的嫩绿。P1 共生尾声、动物、花果、嫁接、天气和额外房间不进入 P0 资产清单。

### 5.2 感知模式

感知开启时冻结模拟，压低背景，突出与当前选择相关的供水路径、光域和攀附点。光用金色疏斜线、太阳图标及强/普通/弱/暗文字；水用青蓝曲线、滴形与当前可用供水；支点用夹持形符号。地下未知区保留遮罩，只有已发现区域与玩法允许的模糊线索被显示，不能由特效无意泄露全关水源。

正常模式保留必要的危险提示；感知模式补足原因而不创造另一套规则。可选“按住/切换”与低动态设置。即使关闭声音或把画面转为灰度，仍可通过形状与文本判断当前的缺水、结构风险和遮光。

### 5.3 界面与操作反馈

常驻 UI 只显示普通能量 `E`、供水/需水概况与小型操作入口。供水不足时引导玩家选中远端节点查看原因；概况中的需水必须包含运输损耗；若玩家查看的是基础需水，则另列损耗与选中器官实得水，避免基础总量造成足水错觉。种子储备单列，只在救援相关时解释；不能绘制成普通能量的第二根可消费条。

选择节点后，器官图标使用根、藤、叶、双线枝干四种明确轮廓，费用与不可执行原因就在选项旁边。分叉是从已有地上节点再长一条藤的动作条件，其额外费用按 GDD 显示，不制造独立新器官。拖拽预览用实线表示合法路径、短断线及停止符号表示被阻挡；失败原因用文字，不能只用红绿。

修剪模式突出将失去功能的整棵后代子树，在确认前显示受影响叶数、边数与需水变化。切口位置之外的非目标植物保持清楚可见，保证玩家能改选。持有侧芽优惠的伤口只标一次可用状态，用完不再持续发光。

UI 目标是最少主文本对比度 4.5:1、关键图标及边界 3:1，最终以实画面测量；不能仅凭色板断言合格。中文优先项目能够合法打包的字体；系统字体仅用于原型。字体、声音、图片均进入素材来源表，不能默认操作系统附带字体可随游戏分发。

## 6. Godot 资源与导入规范

### 6.1 文件、锚点与格式

建议资源根目录为 `res://art/`，分为 `plants/`、`environment/`、`ui/`、`fx/`；分层母文件和授权资料放项目的 `art_source/`、`licenses/`，避免把巨大工作文件当运行时素材。规范命名为 `类别_对象_状态_编号`，例如 `plant_leaf_wilt_01.png`；场景使用 `.tscn`，资源参数使用 `.tres`。素材记录包含作者/来源、授权、用途、修改说明与人工验收日期。

栅格交付用 RGBA PNG、透明背景、sRGB。叶片统一 128×128 画布，叶柄接点落在画布 `(64,112)`，各状态固定该接点；本地原点通过 `Sprite2D` 偏移或父节点校正到该位置，不能让换状态造成叶片跳动。芽/伤口用 64×64，器官图标源文件 64×64，家具按 256～1024 边长分块。单张环境大图上限建议 2048×2048，超过先拆为功能模块。

SVG 用于可编辑母版、图标与设计图。用于 Godot 的 SVG 图形只用经过验证的基础路径/填充，文本应在交付前转曲或由游戏 `Label` 绘制；本规范板保留可编辑文字，是供浏览器阅读的文档资产，不直接导入当 HUD。复杂滤镜应先栅格化并验收。Godot 默认在导入阶段将 SVG 栅格化，不能把一张导入纹理当作任意放大仍无限清晰的运行时矢量。[Godot 图像导入文档](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_images.html)

### 6.2 导入起始设置

| 资源组 | Godot 导入与显示起始设置 | 人工核对 |
| --- | --- | --- |
| 叶、芽、伤口、UI | `Texture2D`、Lossless、透明边缘处理 | 深色/浅色背景都无白边；透明留白不过大 |
| 环境模块 | `Texture2D`、Lossless；大背景可单独评估有损压缩 | 细裂缝无色块，重复接缝不显眼 |
| 会明显缩小的世界贴图 | 开启 mipmaps，节点使用带 mipmap 的线性过滤 | 拉远时无闪烁；小叶仍可辨认 |
| 固定尺寸 UI | 线性过滤，默认不生成 mipmaps | 1280×720 下文字与图标仍清楚 |
| 曲线纹理 | 小尺寸可重复纹理，仅在接头通过验收后使用 | 弯曲不拉成条码，首尾无明显接缝 |

Godot 4 的二维纹理过滤与重复方式位于 `CanvasItem`/项目默认设置，并非旧版逐张图片的 Filter 开关。开启 mipmaps 的世界资源需配合相应过滤；所有设置在本机 4.7.2 导入一张叶、一段藤和一块墙后确认，再复制到同类资产。[Godot CanvasItem 文档](https://docs.godotengine.org/en/stable/classes/class_canvasitem.html)

P0 使用预绘光斑与简单透明几何表现光束；玩法光照仍由离散光区和叶片遮挡采样决定。画面亮度不能反向成为光能计算依据。先实现 Compatibility 下可用的平色/纹理着色，再评估一层简单纸纹；不把屏幕空间模糊、动态体积光、法线材质、三维粒子作为交付前提。

### 6.3 运行预算与交付检查

美术资源不是按文件数量估显存。RGBA8 的 2048×2048 纹理约占 16 MiB，不含 mipmaps；带全 mipmap 链约增三分之一。P0 美术纹理工作目标总计不超过 128 MiB；工程最终目标以 TDD 实测为准。最多100片活叶不应意味着100套不同纹理；共用纹理与材质，只有必要状态覆盖单独处理。

每批先交一张母资源在 Godot 中验证比例、透明边、接点、状态切换和缩放，再批量导出。`res://` 路径、`.tscn` 引用、大小写保持一致；源图与导入参数进入版本管理，导入缓存处理依工程规则。任何清理/移除均遵守用户约束：整体迁移到 `C:/backup/当日年月日目录`，并向 `C:/backup/log.txt` 追加原路径和目标路径，不能直接删除旧资源或内容。
