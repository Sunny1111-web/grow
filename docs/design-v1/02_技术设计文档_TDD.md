## 1. 技术目标与环境事实

用一棵可修剪、有历史痕迹的树形网络，支撑“生长即移动”。P0 只做 Windows 键鼠单机、2D 横向剖面、一间公寓与窗外视野、15～20分钟体验。没有角色运动控制器、刚体植物、真实流体、动物、天气昼夜或联网。用户负责制作决策、集成与试玩；GPT-6 Astra 协助代码、规格与检查，不能当作另一名独立全职开发者。

已确定采用 Godot 4.7.2 stable、GDScript、Compatibility。现场已实际执行 `Tools/GoDot/Godot_v4.7.2-stable_win64_console.exe --headless --version`，输出为 `4.7.2.stable.official.ed1daf0bf`。同目录模板压缩包内的 `templates/version.txt` 为 `4.7.2.stable`，包含 Windows x86_64 debug/release 模板；模板安装状态尚未验证，尚未完成导出。`Tools/Blender` 为空；Grow 当前只有文档与初始 Git 仓库，无提交、无 `project.godot`。本文不把这些待办写成现成功能。

| 选择 | 对本项目的意义 | 决策 |

以上能力分别参考 [Godot 二维文档](https://docs.godotengine.org/en/stable/tutorials/2d/index.html)和 [Unity 6 Tilemap Collider 2D](https://docs.unity3d.com/6000.0/Documentation/Manual/tilemaps/work-with-tilemaps/tilemap-collider-2d-reference.html)。选择依据是现有工具、团队与范围，不声称做过两引擎性能对比。

## 2. 模块边界与依赖

逻辑坐标使用 u，1u=100 Godot 像素；逻辑 y 轴向上，显示层统一转为 Godot 的 y 轴向下。1600×900参考画面对应16u×9u。输入、显示、关卡编辑全部通过同一个坐标转换入口，禁止直接用屏幕像素计算水阻和悬空长度。

| 模块 | 职责与输入输出 |
| --- | --- |
| `PlantState` | 纯数据：树、器官、资源、伤痕、进度；不引用场景节点 |
| `CommandService` | 接收生长/强化/修剪/救援命令；验证、生成候选状态、统一提交 |
| `GrowthSolver` | 输入方向与环境快照，输出曲线、碰撞结果和候选锚点 |
| `EnvironmentQuery` | 只读查询土壤、硬障碍、攀附面、水接入点、光区与感知范围 |
| `SupportSolver` | 输入几何与锚点，输出各边风险、超载积分及断裂事件 |
| `WaterSolver` | 输入树与接水点，输出总Q、源端需求、每器官实得水与缺水比 |
| `LightSolver` | 输出叶片光系数和遮挡层数；不从屏幕颜色读取照度 |
| `SimulationClock` | 唯一推进者；管理固定tick、冻结理由、催生与事件顺序 |
| `Presentation` | 读取状态与事件，生成线条、叶、动画、声音、预警和感知覆盖层 |
| `SaveService / LevelValidator` | 世代存档与恢复；离线检查关卡数据、保底路线和上限 |

依赖方向为：输入→命令→候选模型→各求解器→提交模型→表现。求解器只返回结果，不直接扣能量、创建场景节点或发叙事事件。场景节点销毁、显隐和动画完成均不得改变植物事实。静态配置使用带类型的自定义 Resource；每局可变状态使用独立数据对象，避免修改共享 `.tres` 导致多局污染。[Resource 文档](https://docs.godotengine.org/en/stable/tutorials/scripting/resources.html)

P0 不引入通用 ECS、数据库、第三方行为树或网络同步框架。规模上限为400条活边与100片活叶（节点数据另计），清楚的数据和遍历顺序优先于复杂优化。

## 3. 固定时间、冻结与快速催生

模拟步长严格为0.1模拟秒。渲染每帧推进独立表现时间；累计器每满足0.1秒才执行一次逻辑。普通速度1倍，F催生3倍；每帧最多补6个tick，超量积压时保留顺序并暂时降速、记录性能告警，不跳过风险tick。窗口失焦立即冻结；长时间恢复后不补离线收益或损伤。

冻结使用理由集合：菜单、感知、拖拽预览、生长动画、失焦、救援预览。任意理由存在，能量、水分配时间、枯萎、超载、触发器与催生一起停止；解除一个理由不能清掉其他理由。累计器保留不足一tick的余量，冻结期间不加入时间。UI输入、相机查看和0.6秒生长揭示动画可继续。Godot 提供暂停与节点处理模式，但玩法计时仍集中在本项目时钟中，不能散落为各节点 Timer。[暂停文档](https://docs.godotengine.org/en/stable/tutorials/scripting/pausing_games.html)

每个tick固定顺序：读取已提交树→计算支撑/供水/光照→更新缺水及超载积分→收集死亡/断裂→统一转化失活子树→重新求解受影响数据→按剩余活叶结算能量→评估教学、出口、救援提醒→发布快照。若祖先和后代同时失活，只处理最高祖先一次。能量钳制到0～40，禁止同tick死亡叶继续收入。

F只在无冻结理由时生效。启动时锁定当前器官所需费用作为停止目标，能量达到目标、达到上限、任一新缺水/结构危险出现、松键时即停止。目标费用不可达、无产能或已经危险时不启动。水与断裂风险同速加快；F不会只加收入。冻结期间也不允许零时间批量施加生长：每条命令完成0.6秒动画并解除输入锁后，才接收下一条。

## 4. 数据模型与命令事务

每个活节点有唯一递增 `node_id`、位置、父边、地上延伸子边列表、根子边列表、叶插槽、锚点ID、状态。每条边保存 `edge_id`、父/子节点、根/藤/强化枝类型、曲线控制点与离散点、实际弧长、一次强化标记、缺水积分、超载积分及创建序号。叶保存挂点、固定朝向、逻辑遮挡轮廓、基础需水、缺水积分。种子是唯一根节点，始终保留。

不可变约束：每个非种子节点恰有一个父边；活体连通且无环；交叉只代表画面交叉，不接管、不嫁接；锚点是对环境的引用，不是连接另一条植物的边。种子最多2条根子边、1条地上初生边；根节点最多2条根子边，根分裂不收地上分叉附加费。地上节点最多2条地上延伸子边，叶独立1片；只有落在允许生根土壤接触区的地上节点另有1个根插槽。没有“在空中任意长根”。

命令携带 `command_id、base_revision、target_id、organ、input_direction、preview_hash`。预览复制轻量状态，调用与提交相同的生成、碰撞、水、结构算法，返回费用、整株变化和拒绝原因；只读真实状态，不生成永久ID、不消费随机序列、不解雾、不收水、不存档。根/藤拖拽位移小于12屏幕像素只选中，不发命令。叶/强化使用两次点击：选器官后先显示候选，第二次点击同一高亮目标才提交；重叠对象用Tab循环候选。它们不受根/藤的拖拽阈值限制。

松开时验证版本、目标存活、插槽、E及上限；版本不一致则重新显示结果，不能擅自用旧曲线提交。通过后在候选模型里一次性扣能量、增加几何、分配ID、更新伤口权益及求解结果；全部成功才替换当前模型并增加revision。失败全不生效。重复收到同一命令ID只返回原结果，不二次扣费。提交之后没有Ctrl+Z；修剪是新的有代价决策。

预览除新段外，要标出因本次长叶/分叉而失水或超载的旧段。预览写“提交后稳定供需”，不假装已经经过0.1秒，更不能提前增加枯萎积分。表现层永远使用该候选曲线揭示生长，避免提交时再次掷随机数。

## 5. 曲线、偏转、碰撞与攀附

普通藤目标弧长1.0u，根0.8u。鼠标距离不增加长度，仅提供单位方向d。没有已感知光/水线索时，对应刺激向量置0；重力方向固定为逻辑坐标(0,-1)。藤取 `v=normalize(d+0.18×光方向+0.06×重力方向)`，根取 `v=normalize(d+0.22×已感知水方向+0.08×重力方向)`，再把相对d的偏转钳制在藤±12°、根±15°。根只用感知半径内的水线索，不能用远处隐藏水源偷偷导航。

曲线为三次贝塞尔：起点P0；起始切向在前段末端切线与v之间按0.35/0.65混合；终止切向为v；设目标段长为L、起始单位切向为t0，初值P3=P0+L×v、P1=P0+0.3L×t0、P2=P3-0.3L×v。先生成，再将P1/P2/P3相对P0的位移一起乘以L/实测弧长以贴合目标长度；最多3次，长度误差须≤0.01u。曲率自然感由固定种子与候选命令序号产生最多±3°偏差，纳入预览，不能影响随机游戏奖励。`Curve2D` 可存曲线并提供烘焙长度和采样，API 具体参数在本机验证。[Curve2D 文档](https://docs.godotengine.org/en/stable/classes/class_curve2d.html)

权威几何使用间距≤0.05u的折线；根碰撞半径0.025u、藤0.04u。每一小段做带半径的扫掠与静态障碍查询，不能仅测试离散点而穿过薄墙。起始连接处排除所属父边的一小段；与其他植物允许视觉交叉，但不形成攀附点。硬障碍阻挡整条命令；P0不自动截短扣原价，也不让碰撞后的路径自行绕出预览范围。

遇到允许攀附的表面，方向在表面切线±25°内且候选末端距表面≤0.12u时，可将末端投影至合法贴附位置；必须重新生成完整曲线、扫掠并验证长度。投影导致超长、穿透或离开允许区域则不吸附，显示原因。根必须位于连续可穿根土壤/裂缝，水区并不自动允许穿过其前方混凝土。

锚点记录表面稳定ID、局部坐标和法线。P0环境不移动，合法锚点强度视为足够，不做家具倾倒。锚点只在命令提交时建立；预览触碰墙面不能给旧株增加支撑。视觉缠绕可以超出线宽，但不改变锚点或水路。强化保留原曲线、锚点和碰撞中心线，只改变显示宽度与规则参数，避免强化后被旧缝隙挤死。

## 6. 结构的确切简化模型

以环境锚点切分悬空区域。若一条边的远端有合法锚点，这条边由环境支承，不参与其祖先的悬空负载，也不继续向祖先传播其后代负载；锚点之后新长的边开始新的悬空区域。种子稳定固定；地下根不参与地上弯矩。没有锚点的枝条，即使贴近墙面也不能自动获得支撑。

对每条未被远端锚点支承的地上边e，从其近端开始沿后代遍历，遇上述支承边就停止进入该分支，得到集合U(e)。定义：

- `D_e`：近端到U(e)中最远植物端点的沿边弧长；叶不额外增加长度。
- `M_e = Σ m_i × (|x_i-x_e| + 0.25×|y_i-y_e| + 0.1)`；边重量放在弧长中点，叶重量放在挂点，坐标单位为u。
- `risk_e = max(D_e / Dcap_e, M_e / Mcap_e)`。它是便于解释的风险分数，不是真实力学量。

| 器官 | 重量 | Dcap | Mcap | 基础需水 |
| --- | --- | --- | --- | --- |
| 藤 | 0.25×长度 | 2.4u | 1.2 | 0.35 |
| 强化枝 | 0.45×长度 | 4.0u | 3.0 | 0.50 |
| 叶 | 每片0.25 | 随挂点承载 | 随挂点承载 | 0.80 |

风险≤0.75正常；0.75～1轻微下垂；大于1至1.5为危险，允许玩家明确承担；任一旧/新边预测风险大于1.5，拒绝生长或强化提交。修剪与救援不受此门槛限制。风险>1时超载积分 `b += (risk-1)×dt`；风险≤1时 `b=max(0,b-2×dt)`；b≥2时该边断裂、其后代一同失去活体功能。例如risk=1.25须持续8模拟秒才断，F催生时也真实加速；冻结时不增加b。

算例：三条1u水平藤连续悬空，末端一叶，首边的D=3；M=`0.25×0.6+0.25×1.6+0.25×2.6+0.25×3.1=1.975`，risk=max(1.25,1.646)=1.646，在第三段末端长叶的方案被阻止；第三段尚未挂叶时风险为1.25，可带警告生长。先把首边强化后，M变为2.095，risk=max(3/4,2.095/3)=0.75；第二边D=2且M=1.075，risk≈0.896，可以通过。另一解法是在第二段末端建立锚点，从那里重新计算悬空区域。

强化每边仅一次，花6E，把藤变成枝；需水0.35→0.5，水阻系数0.12→0.05，重量同时上升。重复点击拒绝，不重复收费。枯萎不暗中降低结构容量；下垂与抖动只改变表现，不移动碰撞、光照采样点或锚点，因此不会产生“抖了一下便断水”的反馈环。

## 7. 水：共享预算、距离损耗与局部分配

W是持续供给率单位，不是背包存货；每tick按当前结构重新分配，没有暂停储水。每个接水fixture含 `aquifer_id、access_id、可用Q、接触区`。接触同一含水层多次，取仍由活根连接的接入点Q最大值：仅W1为12，连上W2后为20，同时连上仍为20；剪断W2且没有其他W2接触即回12。接触点表示同含水层可利用程度，不另有局部出水口流量上限。

P0只有这一含水层，不提前做跨水层结算。每器官可从所有有效接入点中选择阻力最小者；接点到器官沿植物树只有一条路径，水可以沿父子边双向运输，拓扑仍是无环树。源点并列时按access_id固定选择。中继根改善局部距离，但不会复制含水层Q。

根/藤/强化枝的沿程阻力分别为每u 0.08/0.12/0.05；路径上每个具有2条活地上延伸子边的节点另加0.15，根分裂不加此项。同节点只数一次；叶挂在该分叉节点时也计入。边需水放在自身弧长中点，路径只算到中点；叶算到挂点。用当前活体形态计算，不把历史断枝纳入。

对器官i，基础需求为d_i，最小路径阻力R_i，满足它所需的源端水量为 `c_i=d_i×(1+R_i)`。这是一笔明确的运输损耗收费：抵达组织d_i，途中损耗d_i×R_i。没有独立边容量或真实压强求解。

分配按根→强化枝→藤→叶排序，同类按R从小到大、再按永久ID。令剩余q=Q，逐个执行：`spent_i=min(q,c_i)`；`delivered_i=spent_i/(1+R_i)`；`r_i=delivered_i/d_i`；`q=q-spent_i`。没有有效接水点时全部r=0。必须始终满足 `Σspent_i≤Q`，并且 `Σdelivered_i+Σ运输损耗=Σspent_i`。严禁把父节点的Q原样分别交给两个子分支。

该优先级保护维持网络的组织，远端叶通常先缺水，嫩芽状态继承所在边。它有意让一部分组织缺水，不做所有叶均匀变差。UI主项显示“可用供水Q / 满足当前结构所需源端水Σc”，避免只显示基础需水Σd而误报有余水；感知模式可查看选中器官的路径损耗与r。

### 完整手算：总量12，哪片叶先受损

本例是独立水求解测试场景，种子S放在地表，因此可以挂叶；第一章埋在地下的S0不可照搬该叶。树为水源→两条0.8u根→种子S→1u强化枝→节点A；A分成左右两路，每路3条1u藤。S、A及6个藤端各有1叶，共8叶。所有段有环境支撑，本例只观察水；2个根的基础需水合计0.30，枝0.50，6藤2.10，8叶6.40，基础需求合计9.30，仍可能缺水。取源为第二根远端，各层计算如下。

| 分配项 | 数量 | 单件R | 单件源端需求c | 该项总c |
| --- | ---: | ---: | ---: | ---: |
| 近水根中点 | 1 | 0.032 | 0.1548 | 0.1548 |

若玩家立刻剪掉最后那片无水叶，只剪叶本身，省掉1.3504源端需求，但剩余需求仍为12.2033，另一远叶仍缺0.2033；这解释了“一次小修剪不一定足够”。再剪一片低光的第二端叶，总需求变为10.9489，所有剩余器官恢复足水。改为接入W2则Q=20；即便运输路径暂不改善，同样结构也可全部供足。若重算后近源路径更短，需求还会降低，但Q依然只有20。

## 8. 枯萎、光收入与恢复

每个活器官保存缺水积分z。`r<0.95`时 `z += (1-r)×dt`；`r≥0.95`时 `z=max(0,z-2×dt)`。z<6健康，6≤z<12萎蔫，12≤z<24枯萎，z≥24死亡。健康倍率h分别为1、0.6、0.2、0。死亡叶不再需水、不遮挡；死亡边不再输水，其后代作为断连子树失活，留下历史形状。死亡不原地复活，只能从存活挂点或伤口附近长新器官；种子不会被该规则清除。

上例持续6模拟秒且无人操作时，最后叶z=6进入萎蔫，倒数第二叶z≈0.903仍健康。持续到24秒，最后叶死亡；不能声称它一死其他叶就足水：重新计算后剩余需求12.2033，倒数第二叶仍r≈0.84945，之后继续累积。剪掉低效叶、补根或W2才是实际修复。保留这个案例用于防止“统计总需求”与“组织实际恢复”脱节。

光区由关卡标注方向、有效区域、强度1/0.6/0.2/0。若区重叠，取强度最大者，强度同值按fixture_id，不叠加光源刷收入。每片叶固定朝向，仅在生成时朝所选光区轻微旋转；P0不加入额外余弦朝向收益。叶面三个固定采样点朝光源做查询：建筑相交则该射线为0；否则每经过一片不同的其他活叶乘0.5；同叶多次相交只数一次，忽略自身。

有效光系数 `L=区域强度×(三条透射率之和/3)`，健康叶收入 `P_i=1.6×L×h×r_i` E/模拟秒。例：普通光下三条射线透射率1、0.5、0，L=0.3，足水健康叶产0.48E/秒。叶的遮挡轮廓使用逻辑坐标，动画摆动不改变它；同tick生长、修剪后刷新受影响叶，禁止用GPU最终画面采样计算经济。

静态光区不必每帧求解；几何或叶变动时标脏，最近一次结果供10Hz模拟使用。供水/健康仍每tick更新。即使E达到40，水维护与枯萎继续；禁止通过满能量停止时间。

## 9. 修剪、伤痕与不可撤销的历史

Shift进入修剪预览，选叶只剪该叶；选边在其近端剪断该边与全部后代，选节点等价选择其入边。根也可剪，预览必须显示失去的水接点及连带枯萎风险。种子不可剪。预览高亮整个受影响子树，列出失去器官、预计源端需求变化、收入变化、接水点变化，不只写“省水”。

提交免费且返能量0。受影响对象从活体索引转入历史记录，立即停止供水、产能、碰撞、遮挡与承重；保留断口和静态残枝表现。一次剪掉一万历史点不等于创建一万个场景节点：逻辑记录和显示槽分离。断裂/枯死走同一失活流程，但事件原因保留。

在仍存活的剪口父节点记录 `scar_id、位置、原边ID、原因、growth_slot_id、侧芽权益状态`。每一原始地上生长插槽的首次人工剪边可生成一次侧芽权益（单剪叶或根不发）：下一条合法藤减2E、最低1E，不减分叉附加费；无效预览不消费，成功提交才消费。同一插槽后来再长再剪只更新同一伤痕，不重新发权益；非人工断裂、枯死、救援器官都不发。不同权益不能叠加到同一命令，因此不能反复剪廉价枝刷永久折扣。

每关最多400活边、100活叶，超过则拒绝新生长并提示修剪；救援在候选模型中先退守普通活体，再建立2条固定根和1片子叶，事务提交后的总数仍在400/100上限内；不能以旧株已满为由拒绝救援。200个伤痕/残枝表现槽满时，最旧空间邻近残枝合批为静态笔触；完整事件和权益记录仍保留，并提示“旧痕迹已合并显示”，不静默丢失数据，也不让历史残枝变成免费支架。

## 10. 防软锁：可重复的退守种子

普通修复优先：免费修剪、接近水源、重新长叶。菜单始终提供“退守种子”，不以E或剧情进度锁定。`E<3且普通叶总产能<0.05E/s`持续3模拟秒时主动提示并暂停；全株失去有效器官也提示。该条件只控制提醒，E=3/4且无可行动作的玩家仍可手动救援。

状态机为正常→提示/预览→退守提交→应急恢复→正常；预览可取消。提交前展示“保留探索与伤痕、所有普通活体退守”，使后果可审阅。提交后执行一笔事务：普通E置0；所有常规活体成为非交互历史形状；种子保留；修复种子旁固定的两段0.8u应急根至W1，以及种子独立应急插槽的固定子叶（表现接点(2,-0.65)，安全光位R0）。不能选择远处目标，不提供任意免费根或叶。

应急根各需0.15W，应急子叶需0.2W，均计入同一Q和正常路径损耗；固定W1的12足够。子叶只响应种子裂缝处专用、不可被普通枝叶遮挡的安全光fixture，足水时产1.0E/秒。它不是全场新增光源，普通叶无法利用；不依赖天气、昼夜或外部重开。本次应急子叶累计最多产18E，之后休眠并停止维护；应急根保持接水。18E恰好可支付安全路线3藤15E+1普通叶3E；这条路线必须在关卡检查器和真实输入回放中验证，已有免费应急根不再重复计入成本。

玩家再次误花预算仍可再次退守。每次都清零普通E、当次常规活体和子叶产能计数，再恢复同一套固定器官；绝不累计多个子叶。应急器官不可修剪、强化、分叉、作为侧芽奖励来源，应急阶段新的地上路线只从种子合法地上芽开始；种子未占用的普通根插槽仍按常规规则可用。接上正常光叶后可以自然继续发展，应急子叶剩余额度不追加。

反复救援的可保留结果只有探索信息、叙事记录和合批伤痕，没有能量、远端结构、W2接入资格或额外权益；叙事事件只触发一次且P0无资源奖励。出口仍要求当前活藤真正抵达，历史到达不能通关。救援不能成为收益循环，但允许无限次重新尝试；这是以重新塑形换恢复机会，不是把旧存档倒回去。

## 11. 存档版本、原子提交与损坏恢复

存档包含 `schema_version、rules_version、level_id、level_revision、engine_build、generation、checksum`，以及全部树数据、E、积分、模拟tick、永久ID计数、探索、已触发事件、伤痕权益和救援额度。不保存临时预览、渲染节点引用或墙钟离线时间；恢复后先重算水/光/支撑，再开放输入，不能依赖过期缓存。

仅在完整tick/命令事务边界取得快照；生长动画期间存档记录已提交的最终曲线，读档时可以直接显示完成状态。每10条有效命令、关键教学点、退守和退出时提交一代。候选JSON按ID排序序列化，并保存校验摘要。大于硬上限、重复ID、有环、孤儿节点、非有限数、超范围E或缺失fixture引用均视为无效。

为遵守不删除/覆盖内容的项目约束，采用“不可变世代文件”实现逻辑上的原子替换：在 `user://saves` 写唯一代号的 `.tmp`，flush并关闭，重新读取校验后，在同目录改名为尚不存在的 `.json`。读取器只承认校验通过的最终扩展名文件，并选择最高有效世代；旧世代不覆盖、不删除。这样提交前只能看到上一代，提交成功后看到新一代；无需覆盖固定的 `save.json` 指针。

Godot提供FileAccess写入/flush与DirAccess改名；官方API本身不是对所有文件系统断电持久性的保证。实现必须检查返回码、确认目标不存在，同卷提交，并用中途终止测试验证；`flush`也不能被描述为电源故障下百分百安全。[FileAccess](https://docs.godotengine.org/en/stable/classes/class_fileaccess.html)、[DirAccess](https://docs.godotengine.org/en/stable/classes/class_diraccess.html)

启动从高世代向低世代验证，损坏最新代时读取前一有效代并明确告知恢复位置；残留.tmp保留诊断，不当作进度。规则迁移写新世代，旧文件原样保留；仅支持已写明的相邻schema迁移，未知未来版本不强行载入、不覆盖。全部代均坏时允许新建独立存档并保留损坏文件，不能静默重置原槽。

P0不提供自动清理历史文件。开发中若确需替换文档/资产，先整体迁移至 `C:/backup/当日年月日/唯一名称`，再向 `C:/backup/log.txt` 追加“原路径：…  => 目标路径：…”；不得把Git或存档备份当成直接删除的许可。

## 12. 场景、关卡工具与感知

建议场景根下设静态环境、玩法fixture、植物表现、历史表现、光感覆盖、UI和相机；玩法状态不跟随场景树层级。房间白盒范围采用x=0～24、y=-4～10，种子(2,-0.8)，W1(2,-2.4)，首个普通光区x=3.2～5.0、y=1～2.5。具体攀附面与路径以GDD关卡图为准。

设计师以稳定ID放置土壤多边形、硬障碍、攀附折线、水接入区、光区、感知线索、出口和应急fixture；装饰图不能自动兼任碰撞。通过Godot `@tool` 脚本显示长度、方向、吸附范围、光射线与水层ID，并提供一键数据检查。官方支持在编辑器运行工具脚本，具体生命周期须本机验证。[编辑器工具脚本](https://docs.godotengine.org/en/stable/tutorials/plugins/running_code_in_the_editor.html)

检查器必须报告：ID重复；光区未设方向；水点落在不可生根区域；装饰遮住关键节点；不足0.08u的不可通过假缝隙；W1/W2含水层ID不一致；首根两段接水失败；初始30E不能走完2根+3藤+1叶=26E；应急18E路线失败；首光被应急历史笔触影响；出口可被单段跨越；锚点失效；普通流程与救援预算不足。设计师可明确标记故意不可走的错误路线，检查报告不得自动修改场景。

感知冻结模拟，已探索区完整显示；根尖1.2u范围揭示地下，2.4u内最近尚未揭示的资源线索提供模糊方向。W1到W2间固定线索C1(3.6,-2.4)、C2(5.2,-2.5)、C3(6.8,-2.6)，根进入1.2u后记为已揭示，再指向下一线索或W2；线索不提供Q。探索标记和已揭示线索一起保存，并逐0.8u增长步长验证提示连续。只有提交后的根推进才扩展探索，取消预览不获得地图信息。迷雾数据用小网格或多边形覆盖，固定在关卡坐标；保存探索结果但不保存整张屏幕图。

## 13. 性能预算与可诊断性

目标为用户实际Windows机器、1920×1080、60帧，记录CPU/GPU/RAM、系统、驱动与构建；在400活边、100活叶、200历史表现槽的压力场景，整帧p95≤16.7ms，单次10Hz逻辑p95≤3ms，完整预览求解p95≤8ms，常规命令提交≤100ms，加载有效存档≤2秒。这些全部是待测门禁，不是本次获得的跑分或最低配置承诺。

结构与树遍历先用清楚的线性/小规模遍历；多接点水路缓存最小阻力；环境折线用空间网格筛候选；光照只在相关变化时标脏。曲线采样点复用，静态残枝合批；不要每片叶每帧创建三条场景射线节点。Godot自定义绘制可集中绘制大量简单形状，减少节点管理开销。[自定义二维绘制](https://docs.godotengine.org/en/stable/tutorials/2d/custom_drawing_in_2d.html)

调试覆盖层显示选中对象ID、revision、Q/Σc、r、z、D、M、risk、b、光射线、冻结理由、当前救援额度。日志记录命令结果、拒绝原因、断裂原因和存档恢复，不记录每帧坐标海量刷屏。固定输入方向/序号与数值快照用于同机回放；不承诺跨CPU浮点逐位一致，验收按几何误差≤0.01u、资源误差≤0.0001。

最大的技术风险是预览与事实分叉、水分配难懂、保底路线因关卡改动失效、伤痕表现失控，以及Godot版本/模板没有完成实际导出验证。对应降级为：保持共享求解器；先显示源端总需求和选中路径；将两条保底路线设为每次改关必跑门禁；保留逻辑记录并合批显示；第一周导出空白可运行包。不得通过关闭水维护、免除所有结构风险或无限发能量来掩盖失败，这会使核心玩法失效。P1共生只在P0验收后设计独立共享水契约，P2器官/天气不进入当前实现。
